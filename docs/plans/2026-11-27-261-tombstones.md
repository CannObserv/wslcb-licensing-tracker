# #261 durable not-a-name

Design: [#247 spec §5](../specs/2026-11-23-247-entity-name-linking-design.md)
(approved, merged `12f9052`). This plan says how §5 lands on the code as it
stands after #262–#269, and where it departs from the spec's letter.

## Problem

`mark_not_a_name` writes a manual `not_a_name` row. The next
`reclassify-entities` deletes the entity along with that row, and a later
`reprocess-entities` brings the string back as a fresh, unclassified entity.
`IL` and `IL IL` were lost this way in #214. A full reprocess, which #267
needs in order to bring 128,014 records up to the current version, would
re-add their 11 links on 7 records.

## Re-measured on prod (read-only, 2026-11-27)

- **There is a second tombstone today:** `ASSOCIATES, LLC` (20239). It has a
  current manual `not_a_name` row from #264's worked case on 11-26, no open
  flag, and 2 `previous_applicant` links (records 17941 and 19491). The spec
  says its links should go, durably. The next `reclassify-entities` would
  purge it the old way. No timer runs that command.
- **`IL` / `IL IL` are absent.** The 7 records still print them. The #214
  backup (`data/remediation-backups/2026-11-06-214/`) holds both entity rows
  and both manual rows; the #211 copy isn't needed.
- **The audit name is already done.** Since #247, `_audit` writes `name` into
  every `entity.classify_*` row, so the issue's "Audit" item is met.
- **`protected_ids` is already done.** #262 added the manual alias and
  dismissal clause, and #269 added verdicts.
- **A plain substring prefilter can't serve the clear path.** `%IL%` matches
  15,661 of 128,758 records, too many to reprocess inside a web request. A
  token-bounded match finds 101 records (13 for `ASSOCIATES, LLC`).
- **Enrichment versions:** `entities` is at v6 on 744 rows. 128,014 rows are
  behind: 16,152 at v1 and 111,862 at v2.

## Approach

A tombstone is an entity whose current manual answer is `not_a_name`
(`tombstone_ids`, which already exists). It keeps its entity row and every
classification row, and it has no `record_entities` links. One helper,
`unlink_tombstones(conn, ids)`, deletes their links, renumbers positions and
relinks their alias mates (the link half of `_purge_entities`).

- **`reclassify_entities`:** the purge set becomes regex noise only. The
  tombstones are unlinked instead of deleted. The result dict gains
  `tombstones` and `tombstone_links`, and the CLI prints them.
- **Extraction:** `extract_entity_names(..., skip=)` takes a set of
  lowercased tombstone names. `parse_and_link_entities` skips them before
  `get_or_create_entity`, so no entity row is ever made for one.
  - `tombstone_names(conn)` loads the set once per reprocess, ingest batch
    and backfill. A caller that passes nothing gets one small query per call.
  - `db check` and the WAC verify pass the same set, so a tombstone never
    reads as a missing link.
- **`STEP_VERSIONS["entities"]` goes from 6 to 7.**
- **Public pages:**
  - `/entities` excludes tombstones.
  - `/entity/{tombstone}` returns 404 to the public. An admin gets the page
    with its classification panel and a "Not a name: unlinked from N
    records" banner.
- **Leaving tombstone state** means `clear_override`, or a manual row of a
  real type over a tombstone (`set_classification` / `accept_answer`).
  - Both reprocess the records whose four applicant columns
    (stored and raw) match the name token-bounded and case-insensitively:
    `(^|[^[:alnum:]])NAME([^[:alnum:]]|$)`, with NAME regex-escaped.
  - Extraction then decides which links come back. The audit row records
    `records_reprocessed`.
- **Restore command:** `wslcb db restore-tombstones --backup DIR
  [--dry-run] [--admin-email]` reads `entities.jsonl` and
  `entity_classifications.jsonl` from the backup.
  - For each entity whose latest manual row there is `not_a_name`, it
    recreates the entity under its **original id**, name and `created_at`.
    The original id keeps the #214 audit rows (38, 40) pointing at it.
  - It writes the manual row with its original `created_by`, `created_at`
    and a note citing #247 §5, #261 and the backup path.
  - It adds a fresh regex row and resolves the entity, then writes one
    `entity.tombstone_restore` audit row. Attribution comes from
    `couple_seed.resolve_admin`, so the code carries no email.
  - It refuses an id that holds a different name, and a name already held
    by another id. A rerun reports "already restored".

## Tradeoffs / alternatives

- **Unlink only in `reclassify-entities`, as the spec says.** Between the mark
  and the next run, a record's chip would link to a page that 404s for the
  public. My call: `mark_not_a_name` unlinks at once, in its own
  transaction. Reclassify still sweeps up older marks, 20239 included.
- **Unlink only `confirmed_noise_ids` (no open flag), as the issue says.**
  Extraction skips every tombstone whatever its flags, so the next reprocess
  would drop those links anyway. My call: one definition, `tombstone_ids`,
  everywhere. An open flag still keeps an entity out of Jev, as it does
  today.
- **Restore through the startup `data_migrations` registry.** That would run
  against every database, test and fresh ones included, where the backup
  file doesn't exist. A CLI command (the #269 precedent) runs once, on
  prod, after a backup.
- **Embed the two rows in code, as `SEED_246` does.** The manual rows'
  `created_by` is an email, so embedding them would commit it. Reading the
  backup avoids that.
- **Substring prefilter (spec wording).** It returns 15,661 records for
  `IL`. The bounded match is still a prefilter, and extraction still
  decides.

## Steps

1. **Core, red then green:**
   - `tombstone_names`, `unlink_tombstones`, and the reclassify change.
     Tests: a tombstone survives reclassify, its links are gone and its
     positions are compacted, and regex noise is still purged.
2. **Extraction skip:**
   - `skip=` on `extract_entity_names` / `parse_and_link_entities`.
   - Preload in reprocess, ingest (`pipeline`), `backfill_entities`,
     `db check` and the WAC verify.
   - Bump entities to v7.
   - Tests: tombstone → reclassify → full reprocess links nothing and
     creates no entity row; ingest skips too; `db check` stays clean.
3. **Mark and leave paths:**
   - `mark_not_a_name` unlinks.
   - `clear_override` and a real-type manual row over a tombstone
     reprocess the bounded-match records.
   - Tests: mark → links gone; clear → the same links back; a reprocessed
     non-matching record is untouched.
4. **Public and admin pages:**
   - `/entities` filter, 404 for the public, admin banner.
   - Route tests for both audiences.
5. **`wslcb db restore-tombstones`:**
   - Tests use a fixture backup dir: restore, then rerun ("already"), then
     the refusals, then dry run.

  rehearsal diff may show changes beyond the tombstones (older cleaning).
  Those are #267's catch-up, but you see them before prod runs it.
- **Full reprocess cost:** it rewrites about 208K links and every `party_id`.
  I'll time it on scratch, run it outside the scrape window (08:31Z daily),
  and vacuum after.
- **Unlink at mark time** is my call (above). Say if you want the spec's
  reclassify-only timing instead.
