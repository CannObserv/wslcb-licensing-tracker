# Identifying User-Agent (#243)

## Problem

WSLCB's AWS WAF flags our scrape partly because it sends httpx's default
`python-httpx/<v>` User-Agent (#198). The owner agreed with WSLCB staff that
we'll identify ourselves as a versioned Cannabis Observer process with a
contact address. The owner's direction (2026-11-02): use it on **every
outbound client**, with the email from a required, syntax-validated
environment variable.

## Approach

`config.py` builds one string:

```
CannObserv-wslcb-licensing-tracker/<package.version> (+https://github.com/CannObserv/wslcb-licensing-tracker; <email>)
```

- **The version** comes from `importlib.metadata`.
- **The email** comes from `CO_WSLCB_LICENSING_TRACKER_CONTACT_EMAIL`, following the
  `ENV_PREFIX` convention for variables added from #204 on. The issue said
  `WSLCB_CONTACT_EMAIL`, which predates checking the convention.
- **Validation** is syntax only: a conservative pattern that by construction
  excludes the `(`, `)`, `\`, space and control characters that would break
  the header's comment syntax.

Every client then sends the string:

| Client | Where | On a missing or invalid email |
|---|---|---|
| WSLCB fetch | `scraper.scrape()` | **strict**: the run fails before sending, with its own fault key |
| Address validator | `address_client` shared client, now built lazily | strict |
| Jev | `jev_classifier` client it creates | strict |
| co-status check-in | `checkin._http_post` | **degrades**: logs an ERROR, sends the UA without the contact |
| GCS | `backup` / `restore` storage clients, via `ClientInfo` | degrades, the same way |
| Mac relay `curl` | `relay-capture.sh` gets the string from the VM (`wslcb ops user-agent`) over ssh each run | strict: no fetch without it |

## Tradeoffs / alternatives

- **Strict everywhere:** rejected. The check-in is the alarm system. If a
  config slip made it raise, the alert reporting that very failure would never
  be sent, and only the dead-man silence would fire, about a day later. A
  restore during an incident shouldn't be blocked by a contact email either.
  These paths still send the full UA whenever the variable is set; they only
  refuse to *fail* over it.
- **Baking the UA into the Mac's plist at install:** rejected. It goes stale
  when the version changes, and duplicates the validation. Asking the VM costs
  one extra ssh round trip per run.
- **The `email-validator` package:** rejected. That would be a new dependency
  for a syntax check a pattern covers, and live checks are out of scope by
  direction.

## Steps

1. `config.py`: `contact_email()` (raises `ContactEmailError`), `user_agent()`
   (strict) and `user_agent_or_fallback()` (lenient). Tests. `conftest.py`
   gets an autouse fixture that sets a valid test email.
2. Strict clients: the scraper, a lazy address client, Jev. Tests check the
   header, and that a missing email fails the scrape with fault
   `ContactEmailError` before any request.
3. Lenient clients: the check-in and GCS. Tests check the full UA when set,
   and the fallback plus an ERROR log when not.
4. `wslcb ops user-agent`; `relay-capture.sh` fetches it and sends it with
   `curl --user-agent`. Tests.
5. Docs: `.env.example`, DEPLOYMENT (prod env), RECOVERY (`backup.env`),
   MONITORING (the config fault), RELAY.
6. Deploy: **set the variable in `/etc/wslcb-licensing-tracker/.env` and
   `backup.env` first**, then merge, restart the web app, and confirm the
   string on the VM.

## Open questions / risks

- `pyproject.toml` is still at `0.1.0`, so the UA reads `/0.1.0` until
  releases bump it (#243 open question).
- The owner reinstalls the relay script on the Mac to pick up the new curl
  User-Agent. The old script keeps working in the meantime.
